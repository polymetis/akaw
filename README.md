# Akaw

An Elixir client for the [CouchDB](https://couchdb.apache.org/) HTTP API.

Akaw is a thin, complete wrapper: endpoints are plain functions returning
`{:ok, decoded}` or `{:error, %Akaw.Error{}}`, with no schema layer, no
changesets, and no process to supervise unless you want one. It covers the
whole 3.x surface — documents, attachments, views, Mango, design functions,
partitioned databases, replication, and the cluster administration endpoints —
and it streams large responses properly rather than materialising them.

Speaks directly through [Finch](https://hex.pm/packages/finch) with the
OTP-native `JSON` module — between your call and the socket sit exactly
one HTTP client and one parser.

## Installation

```elixir
def deps do
  [
    {:akaw, github: "polymetis/akaw"}
  ]
end
```

(From git while 0.1.0 is unreleased; once it lands on Hex,
`{:akaw, "~> 0.1"}`.)

Requires Elixir 1.18 or later (Akaw uses the built-in `JSON` module) and
CouchDB 3.x.

## Quick start

```elixir
client = Akaw.new(base_url: "http://localhost:5984",
                  auth: {:basic, "admin", "password"})

{:ok, _}    = Akaw.Database.create(client, "mydb")
{:ok, _}    = Akaw.Document.put(client, "mydb", "user_42", %{name: "alice"})
{:ok, doc}  = Akaw.Document.get(client, "mydb", "user_42")
{:ok, page} = Akaw.Documents.all_docs(client, "mydb", include_docs: true, limit: 50)
```

The client is a plain struct. Build it once and pass it around — there is
nothing to start and nothing to supervise.

## Errors

Every failure arrives as one shape, so `case` and `with` stay readable:

```elixir
case Akaw.Document.get(client, "mydb", "missing") do
  {:ok, doc} -> doc
  {:error, %Akaw.Error{status: 404}} -> :gone
  {:error, %Akaw.Error{status: 409}} -> :conflict
  {:error, %Akaw.Error{} = error} -> raise error
end
```

HTTP failures carry `status`, plus CouchDB's `error` and `reason`. Transport
failures (DNS, refused connection, timeout, TLS) have `status: nil` and keep
the original exception at `body.exception`.

> For transport failures, treat `:reason` as display-only and branch on
> `body.exception`. `:reason` is generated by the transport layer, and its
> wording changes between Erlang/OTP and Finch releases.

## Streaming

Anything unbounded — a continuous `_changes` feed, `_all_docs` over a large
database, a whole view, a big Mango result — should be streamed. Akaw offers
two flavours, and the difference matters:

**Lazy `Enumerable`** — ergonomic, but it uses the calling process's mailbox,
so run it from a process you own (a `Task`), never from a GenServer or
LiveView:

```elixir
Task.async(fn ->
  client
  |> Akaw.Documents.stream_all_docs("mydb", include_docs: true)
  |> Stream.map(& &1["doc"])
  |> Enum.take(1000)
end)
```

**Synchronous callback** — the reducer runs inline, so no messages reach your
process and blocking in the reducer applies real TCP backpressure to CouchDB.
This is the one to use from inside a GenServer or LiveView:

```elixir
{:ok, count} =
  Akaw.Documents.reduce_while_all_docs(client, "mydb", 0, fn _row, count ->
    {:cont, count + 1}
  end)
```

`Akaw.Changes.reduce_while/5` works the same way but subscribes to a
*continuous* feed, so it runs until your reducer returns `{:halt, acc}` — it
will not stop on its own just because the database is currently quiet. Give it
a `:heartbeat` so idle periods do not look like a stalled connection; Akaw
derives a matching `:receive_timeout` from it automatically:

```elixir
{:ok, seen} =
  Akaw.Changes.reduce_while(client, "mydb", [], fn change, seen ->
    if change["id"] == "the_one_i_was_waiting_for" do
      {:halt, [change | seen]}
    else
      {:cont, [change | seen]}
    end
  end, heartbeat: 10_000)
```

Both flavours exist for `_changes`, `_all_docs`, `_design_docs`, views,
`_find`, `_db_updates`, and the partitioned equivalents. See the `Akaw`
moduledoc for the full list.

## Authentication

```elixir
Akaw.new(base_url: url, auth: {:basic, "admin", "password"})
Akaw.new(base_url: url, auth: {:bearer, token})
Akaw.new(base_url: "http://admin:password@localhost:5984")  # lifted into :auth
```

For cookie auth, `Akaw.Session.create/3` returns a client carrying the
`AuthSession` cookie, and `Akaw.SessionServer` is a GenServer that holds one
and refreshes it on a timer:

```elixir
children = [
  {Akaw.SessionServer,
   name: MyApp.Couch, base_url: url, username: "admin", password: "password"}
]

client = Akaw.SessionServer.client(MyApp.Couch)
```

`:password` also accepts a 0-arity function, so the secret can be fetched at
refresh time rather than at boot.

`Akaw.Client` redacts credentials in `inspect/1` output — including a session
cookie in `:headers` and anything tucked into `:req_options` — so a client
sitting in process state will not leak secrets into a crash report.

## Connection pooling

Akaw is an OTP application: it boots one Finch instance named
`Akaw.Finch` (one HTTP/1 pool of 50 connections per CouchDB host), and
every client uses it with zero setup. To use your own — bigger sizes,
TLS options for a self-signed CouchDB, a proxy — start a Finch in your
supervision tree under a name of *yours* (never `Akaw.Finch`; akaw's
copy boots first and yours would fail with `:already_started`):

```elixir
children = [{Finch, name: MyApp.Finch, pools: %{default: [size: 200]}}]

client = Akaw.new(base_url: url, finch: MyApp.Finch)
```

Per-call transport escape hatches (`:receive_timeout`, `:pool_timeout`) are
accepted wherever they make sense. Client-level options are a narrow, named
set — see `Akaw.new/1` — and connection-level options (TLS for self-signed
CouchDB, proxies) belong on a named Finch pool as above.

## Testing against Akaw

For tests, serve a stub plug from a loopback listener and point the
client at it — the request travels the real transport, so your tests
can't drift from what production sockets do:

```elixir
# test/support/fun_plug.ex — Bandit mounts a module plug; this one
# closes the gap to anonymous functions.
defmodule MyApp.FunPlug do
  @behaviour Plug
  def init(fun), do: fun
  def call(conn, fun), do: fun.(conn)
end

# In a test:
plug = fn conn ->
  conn
  |> Plug.Conn.put_resp_content_type("application/json")
  |> Plug.Conn.send_resp(200, ~s({"ok":true}))
end

server =
  start_supervised!(
    {Bandit, plug: {MyApp.FunPlug, plug}, ip: {127, 0, 0, 1}, port: 0, startup_log: false},
    id: make_ref()
  )

{:ok, {_address, port}} = ThousandIsland.listener_info(server)
client = Akaw.new(base_url: "http://127.0.0.1:#{port}")
```

(Needs `{:bandit, "~> 1.0", only: :test}` — and `{:plug, "~> 1.0",
only: :test}` too, since the snippet names `Plug.Conn` directly.)
`port: 0` binds a fresh OS-assigned port per test, so `async: true`
suites can't collide.
Akaw's own unit suite runs on this seam — `test/support/akaw/loopback.ex`
in this repo is the helper form of the above, and lifting it wholesale
is encouraged.

## Development

The test suite is split in two. Unit tests serve stub plugs over
loopback sockets — the real transport end to end — and need nothing
running:

```console
$ mix test
```

Integration tests run against a real CouchDB, which is where the wire
behaviour actually gets proven:

```console
$ docker run -d -p 5984:5984 -e COUCHDB_USER=admin -e COUCHDB_PASSWORD=password couchdb:3.5
$ mix test --include integration --max-cases 4
```

`--max-cases 4` is not optional: at higher concurrency CouchDB 3.5's auth
lockout kicks in and the run fills with spurious 401s. Point the tests
elsewhere with `AKAW_TEST_URL`, `AKAW_TEST_USER`, and `AKAW_TEST_PASS`.

Both suites run on every push and pull request against a real CouchDB
service container — see [`.github/workflows/elixir.yml`](.github/workflows/elixir.yml).
